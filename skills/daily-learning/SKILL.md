# Daily Learning

Teach toward the learner's desired ability through one manageable concept and one practice activity per lesson. Work with the capabilities of the current app; this skill itself provides no browsing, transcription, storage or scheduler.

## Set up or resume

1. Reuse known answers. Ask together for subject, desired outcome, current level, minutes available, language and relevant constraints. Offer “unknown” where appropriate. Ask delivery time and timezone only when scheduling is requested. Beginners need useful defaults, not a long questionnaire.
2. Inspect tools available in this conversation. Record research, transcript access, file/PDF creation, durable context and scheduling as **available**, **verified**, **unavailable** or **unknown**, with a short reason. A tool listing establishes availability; successful relevant output establishes verification. Do not execute side effects merely to test access.
3. If transcripts need connecting, read [Supadata setup](references/supadata.md). Progress with credible written sources while an optional connection is pending; state the source change. If browsing is unavailable, offer to teach from provided material or general knowledge, labelled accordingly, rather than presenting that as live research.
4. Propose seven small learning objectives in prerequisite order, tailored to the goal. Create the first lesson using [the lesson workflow](references/lesson-workflow.md). Use [the learner profile template](assets/learner-profile.md) and [learning log template](assets/learning-log.md) in accessible storage, or keep equivalent structured records in the current conversation.
5. Deliver the preview and ask one useful feedback question. Provide a short setup status: what worked, what is missing and where records live. Leave recurring delivery off for a test. For an explicit scheduling request, read [scheduling and continuity](references/scheduling.md).

For later lessons, retrieve the profile and latest learning log first, then follow the lesson workflow. If records cannot be read, disclose the gap and use the available conversation. Never infer that a delivered lesson was read, understood or implemented.

## Scope

Version one supports one learning track, YouTube videos with existing captions (including podcasts on YouTube), and accessible written sources for verification or fallback. Prefer instructional relevance and evidence over recency, fame or low view counts. Use current information where the topic requires it.

Adapt practice to the subject: a coding exercise, a language recall task, a photography assignment or a management decision. For medical, legal, financial or safety-critical topics, use suitable current authoritative sources, establish relevant jurisdiction/context, and keep practice educational rather than prescribing consequential personal actions. State when a visual demonstration, hands-on feedback or qualified supervision is needed.

Use original explanations and short attributed excerpts, not full third-party transcript redistribution. Account authentication belongs in the provider's connection flow. Request neither passwords nor API keys in chat. Changing a workflow's instructions does not install tools or guarantee execution.
